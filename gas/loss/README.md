# 每日耗損 V3：當日累計、只入帳差額

網站與耗損表使用同一份 Google 庫存日欄。識別為「完整日期＋廠牌類別分頁＋藥品編號」，並核對名稱。

- 第一次填 2：扣 2；再次填 2：不變；改 3：只扣 1。
- 改小或歸零：必填更正原因，差額加回庫存。
- 留白不修改；0 是明確歸零。不要把每次新增使用量當成當日累計。
- Google 預覽後才可確認，期間庫存或已入帳量變動即拒絕舊預覽。

## Google 耗損表

六個分頁：科達、天明、富田，各分單方／複方。
D1 是固定日期；E1 是已載入日期。D 欄當日累計、E 欄已入帳、F 欄差額、G 欄原因。
E/F 受保護，E 只是顯示快照；GAS 重新讀取目標日欄，不信任前端或 E/F 計算。

```excel
=IF(D3="","",IF($D$1<>$E$1,"請載入日期",IF(AND(ISNUMBER(D3),D3>=0,ISNUMBER(E3),E3>=0),D3-E3,"請檢查數字")))
```

重新整理試算表後，使用「💊 庫存管理系統」選單：
1. 清除已核對的舊 D 欄輸入，再改 D1 日期。
2. 載入已入帳耗損；如當日日期欄不存在，使用「建立所選日期欄」。這會在庫存各分頁末尾新增該日期，不改歷史日欄。
3. 填累計量；調低時填 G 欄原因。
4. 預覽累計並確認差額。

港香蘭沒有對應的庫存分頁，保留原表，不納入自動扣庫。新增品項先在庫存表建立完整編號、名稱與實際瓶數，網站重新讀取後可使用。舊版會清空 D:F 的同步函式已停用。

## 網站

維持六分頁清單，顯示雲端瓶數、已入帳、當日累計、差額、登錄後瓶數。不再顯示「本機瓶數」。
網站先送草稿至 Google 確認頁，Google 讀取最新資料後預覽；確認才入帳。沒有將真實藥庫資料送至 GitHub。
網站未送出輸入只保留於本次頁面；切換日期時要求先清除輸入。網站重新讀取快照可能受 Google CSV 快取影響，最終以 Google 預覽為準。

## 安裝與存取

執行 `node scripts/build-loss-gas.mjs` 產生 Code.gs。線上四檔使用 Code.gs、WebApp.gs、LegacyItems.gs、appsscript.json。
啟用 Sheets v4。Web App 以部署者執行、只有自己可存取（MYSELF），使用已授權的部署者 Google 帳號；不公開匿名寫入。
Web App GET/POST 都只顯示草稿；實際寫入由 `lossV3Commit` 執行，需登入及有效預覽 token。
`lossV3ReadOnlyCheck` 可從編輯器執行，沒有庫存寫入。既有按鈕 `openCuteConfirmDialog` 保留；V2 的直接扣庫函式停止接受呼叫。

## 一致性與更正紀錄

庫存 G、新累計日欄、版本防重鍵與 `耗損V3_更正紀錄` 在同一 Sheets batchUpdate 原子提交。ScriptLock 序列化此 GAS 內的交易；命名範圍版本鍵阻止超時後的延遲重複寫入。
紀錄含原累計、新累計、差額、庫存前後、帳號、經手人、時間與原因。原 V2 歷史不刪除；V3 首次採原表指定日期量為既有基準，不重扣歷史。
外部人工直接修改 G 或日欄不受 ScriptLock 保護；正式操作請透過確認流程。V3 已有紀錄後若日欄被人工改到與紀錄不符，停止扣庫供核對。
來源表 E 的回填是顯示更新，若失敗不會再扣庫；重新載入即可。不要刪除交易紀錄或 `loss_v3_` 命名範圍。
歷史週合計保留；預估庫存天數 J1 改用動態每日欄，排除入貨與週合計重複計算，詳見 formulas.md。新日期補在末端，不會重新標記舊日期。舊週合計只涵蓋原本的週範圍。
