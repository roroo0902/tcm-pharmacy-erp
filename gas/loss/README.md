## 每日操作

1. 核對上日已入帳，保存資料，再清空上一日 D:F 數量與其扣庫註記。不可只改日期而保留舊數量。
2. D1:F1 改為含年份的固定日期，例如 2026/10/28，不可使用 TODAY 等公式。程式不會清除耗損或擅改日期。
3. 核對目標有同年月日及星期欄。缺日期或年份不符需先由管理者修正總表，程式不補造日期、不覆寫合計欄。
4. 預覽核對日期、藥品、瓶數及剩餘量，再確認扣庫。已入帳格不可直接改量，額外用量填 E/F 空格。減量及錯帳需人工核對，本版不提供自動沖銷。
5. 有舊版「已扣庫存」註記的非零格會停止，需先核對舊帳遷移，不可清掉註記後重送舊量。

## 入帳與重試

- 全表驗證通過才寫入。缺欄、重複編號、編號／藥名不符、非數字、負數、無限數、空庫存、庫存不足、目標格公式，皆整次停止。
- 預覽後資料變動會要求重新預覽；同 GAS 專案用 ScriptLock 序列化。其他 GAS 專案及人工編輯不受此鎖保護，入帳期間不要同時編輯庫存或跑進貨／其他扣庫。Google Sheets 無法讓本程式跨其他寫入者做 compare-and-swap。
- 目標 G、每日欄、F、耗損V2_交易紀錄以單一 Sheets API batchUpdate 原子寫入；來源註記只是顯示輔助，失敗不造成下次重扣。
- 鍵由來源表ID、分頁ID、完整日期、編號、D/E/F槽位組成，來源排序不影響識別。同鍵同內容跳過；數量或藥名被改則拒絕。
- 同批建立固定 ID 的 loss_v2_… 命名範圍，讓 API 拒絕重複 ID，防止逾時批次較晚到達時重送。必須保留交易表及這些命名範圍，不可單獨刪除、改名或覆蓋其中一方。
- 逾時代表結果未知；關閉後重新預覽，讀取交易紀錄確認，不要手動重扣。若命名範圍與紀錄不一致，停用並核對。
- JSON 保存日期、來源位置、編號、藥名、數量、庫存及每日量前後值、經手人與時間。無法取得經手人信箱時拒絕寫入。
- 成功、失敗與來源註記未完成分開提示。
