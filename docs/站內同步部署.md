# 站內核對與 Google Sheets 直接入帳

2026-10-29 已取得使用者確認，完成 Cloud 專案切換、Apps Script API 啟用、管理者白名單與 MYSELF API 執行檔第 11 版部署。`web/direct-config.mjs` 已接上部署並啟用，正在進行實際登入與跨裝置驗證；尚未宣告完整線上驗證完成。

## 操作流程

登入 Google → 填寫交易 → 在網站核對最新雲端預覽 → 確認入帳 → 原有 GAS 交易核心寫入並讀回。

建檔、進貨、單筆及批次訂貨、進貨沖銷、取消訂貨、每日累計耗損共用直接呼叫通道。訂貨只建立訂單，不增加庫存。耗損預覽會建立缺少的完整日期欄，確認前不扣庫。

庫存總覽停留前景時每 15 秒重新讀取，切回分頁或完成交易也會重新讀取。這是定時更新，不是即時推播。其他裝置須使用獲准帳號登入；關閉或休眠中的裝置恢復時再讀取。

六個分頁的同步讀取合併成一次 API 呼叫。OAuth token 僅存記憶體，重新整理或過期時重新登入。瀏覽器只保留草稿與待核對交易編號，不把本機帳當正式庫存。網路失敗不自動重送寫入。

執行 `node --test`。新增測試涵蓋帳號白名單、固定來源、防止任意工作簿讀取、預覽不入帳、預覽內容不被後續輸入修改、確認 token、六分頁共用讀取、授權逾期、網路失敗不自動重送，以及耗損入帳後核對。

發布前還須以實際 OAuth 在 GitHub 網址讀取六個分頁，核對 API 執行權限；使用明確隔離的測試品項驗證進貨、重送、累計耗損與沖銷，讀回 Sheets，再用另一個瀏覽器登入檢查更新。此階段不能以單元測試取代線上驗證。

程式回復：`enabled:false` 會回到原 Google 確認頁流程。GCP 專案切換本身不可回復到預設專案；回復前端並不恢復舊授權。
