# 訂貨V2

來源：藥品庫存總表 `1jbiHJoDf730G7qLywlS4UA2tHW5lPRc6wExLW-7Pq4Q`。
目標：訂貨表 `1YcO7XRhN4T8wrL6wn-jD45lqif--rYQF4HCuBE-Nju8`。

`src/orders.mjs` 是純計算核心，供 GitHub 網頁與 GAS 共用。修改後執行 `node scripts/build-order-gas.mjs` 產生 `Code.gs`。

在指定 GAS 專案中，以 `Code.gs` 取代「將庫存表中的耗損量加入.gs」，以 `WebApp.gs` 取代舊「未命名.gs」網頁入口。其他原有列印、AI 檔案保持原樣；舊程式備份只存本機 backups，不公開。

原按鈕仍指派 `runManualSyncRange`。新版只寫入 `訂貨V2_廠商類別` 分頁，保留該表已填確認量，不清空原訂貨表 B:D、L，也不重寫 E1。來源缺少日期時整次停止，不修改舊結果。資料空白保留缺漏；使用者勾選後才按零計算。週日預設排除。

## 計算定義

- 從 N 欄起，只選第2列為一～六（日）／週一／星期一等每日欄位；不選入貨量、耗損量、耗損表等合計欄。
- 完整日期保留年份。月／日文字只在所選最多63日期間中唯一對應時接受。
- 缺日期、重複日期、負耗損、非數字或缺庫存不自動產生建議量。
- 每日平均保留小數。基本建議量 = ceil(max(0, 平均耗損×(備貨+運送+假期天數)−未拆封庫存))。
- 此為明示的新基本補貨規則，並非原表 AI／四週加權模型。原表訂量在網頁上僅對照，不自動採用。
- 無年份表頭的 CSV 顯示值無法證明年份；網頁會標示依所選期間解讀。GAS 可讀到真實日期時保留真實年份。

## 確認訂單

GitHub 草稿保存在該網站的瀏覽器，與庫存交易帳本分離。支援下載 JSON／廠商 CSV、完整訂貨備份與還原。

網頁應用程式部署為「執行身分：我」「誰可以存取：只有我自己」。不要改為匿名可寫，不在公開程式碼放入金鑰。部署完成後，把 Google 提供的 exec URL 寫入 `web/order-endpoint.mjs`，並更新其版本查詢參數。

GitHub 的「送往 Google 確認」以表單 POST 傳送已確認草稿；Google 登入頁再次要求使用者確認匯入。跨來源不以 no-cors 回應推定成功。成功以 Google 頁面顯示及試算表讀回為準。

匯入只新增「訂貨V2_確認紀錄」，狀態為待發送・未入庫。同訂單ID同內容不重複寫入；同ID不同內容拒絕。無任何廠商發送或庫存入帳動作。

`orderV2ReadOnlyCheck` 可在 GAS 編輯器執行唯讀檢查。未取得 Google 授權前，不宣稱雲端寫入已啟用或已驗證。
