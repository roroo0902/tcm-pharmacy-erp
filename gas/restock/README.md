## 已有功能

- `onOpen`加入「庫存管理系統 → 執行進貨入庫」選單。
- `openRestockConfirmDialog`顯示確認與完成畫面。
- `syncRestockToInventory`處理科達單方、科達複方，自第3列讀取A:F。
- 進貨表A為編號、B為藥名、D為本次實際到貨瓶數；程式內部分註解稱D為訂貨量，但現有表頭定義為實際到貨量。
- 依同名分頁與編號，找到總表B欄對應列，將D欄瓶數加到總表G欄。
- 寫入總表F欄日期、K欄缺藥標記、L欄缺藥率、M欄本次到貨瓶數，M1寫日期。
- 無對應編號時會插入新列，A欄標「新增藥品」。
- 入藥表D欄註記含「已入庫」時跳過；處理後批次寫入此註記。

## 程式檢視發現的待修項目

1. **缺少可靠的交易識別與中斷恢復。** 庫存逐列寫入，註記最後才批次更新；若中途失敗，先寫入的庫存可能在重跑時重複增加。未使用鎖定，多人或重複執行也可能互相覆寫或重複計算。只有加鎖仍無法解決寫庫存後中斷的重送問題，應採交易流水與唯一入庫ID。
2. **新增一批進貨沒有獨立識別。** 舊註記保留時，新填的到貨量仍會被跳過；清除註記但沒有建立新單時又可能重複入庫。應以入庫單／明細ID識別每一批。
3. **數量檢查不足。** 只有整列沒有編號、名稱且數量不大於0才跳過；有編號的0、負數或非數字仍會進入同步分支，可能造成減庫或錯誤。應在任何寫入前驗證有限正數瓶數。
4. **錯誤訊息可能誤報成功。** 目標開啟失敗時catch後直接return，前端仍會進入success handler；缺少failure handler，也沒有回傳實際成功／失敗／跳過筆數。
5. **匹配只看編號。** 沒有驗證來源藥名與總表藥名一致；總表編號重複會由最後一列覆蓋索引。不得直接假定不同廠牌、同編號或同名為同一品項。
6. **日期不是完整交易日期。** D1可為TODAY()，程式將日期轉為MM/dd文字寫入，年份與固定交易時間未保存。後續應記完整日期與入帳時間。
7. **部分狀態會覆寫而非留歷史。** M欄保留的是最近一次到貨量；不是可追溯的逐筆進貨帳。K/L狀態也被最新來源覆寫。
8. **分頁範圍有限。** 僅科達單方、科達複方；不包含入藥表中的天明分頁。擴充前需先處理已發現的廠牌與編號衝突。
9. **新增列需要結構驗證。** 新增僅寫A:M，未明確複製同類藥品完整公式、資料驗證與格式；插到表尾的邊界也需用副本測試。

## 與ERP的關係

這份檔案保存既有進貨功能，不代表新的ERP已呼叫或取代它。後續可將「來源單、分頁、編號、藥名、到貨瓶數」先轉為預覽明細，通過主檔核對後再送出交易；確認前不得同時對舊總表加庫存又對新ERP記一次正式進貨。

尚未取得GAS的Script ID、完整專案其他檔案、觸發器與部署設定，因此沒有建立clasp綁定、GitHub→GAS自動推送或線上自動同步。耗損及訂購列印的GAS尚未提供。
