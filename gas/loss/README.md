## 現有行為（依附件程式，非線上欄位驗證）

- 只處理科達單方、科達複方，自第3列讀B編號、C藥名、D/E/F耗損瓶數。
- 各耗損格數量大於0且註記不含「已扣庫存」才加入本次扣除量。
- 目標按B編號匹配；只有來源無編號時才按C藥名匹配。這不是編號與藥名同時驗證。
- 從目標G瓶數扣除；按來源D1日期搜尋目標L:AZ第1列，找到時累加該日耗損；找不到仍扣總庫存。
- 目標F寫入執行當天MM/dd文字，再逐格加「已扣庫存」註記。
- `onOpen`建立選單；`openCuteConfirmDialog`顯示確認視窗，呼叫 `syncLossToInventory`。

## 上線修改前需處理

1. **欄位衝突待核對。** 原進貨程式按目標D欄藥名，本程式按C欄；進貨程式寫L缺藥率、M最近到貨，本程式將L:AZ作每日日期區。需先讀現行總表欄位，再決定修正，不能直接假定兩份設定一致。
2. **中斷重送與同時執行。** 先扣G、累加日欄、寫F，最後逐格註記；任何中斷或多人同時執行都可能重複扣庫。需交易唯一ID、可恢復的入帳流程與鎖定；僅加鎖不足以解決中斷後重送。
3. **註記沒有交易日期及已扣數量。** 修改已註記格的瓶數不會自動扣差額；保留註記填隔日資料會漏扣，清除註記則可能重扣。所謂增量是未註記格的加總，不是數量差額。
4. **日期不完整。** 日期比對及F更新只有MM/dd，跨年可能誤配；F記執行日而非耗損發生日。找不到日期仍扣庫會使每日紀錄與總量不一致。
5. **匹配歧義。** 重複編號或名稱會被最後一列覆蓋；有編號時不檢查藥名一致，找不到編號也不改按名稱。應先驗證唯一主檔。
6. **數量與負庫存。** 非數字被轉0、負數被略過，Infinity未排除；空白或錯誤庫存被當0，沒有防止扣成負數。
7. **成功提示不可靠。** 開啟目標失敗時直接return，缺分頁或找不到品項也跳過；前端仍可能顯示成功，且無failure handler。需回傳成功、跳過、失敗明細。
8. **可追溯性不足。** 未保存完整交易ID、經手人、固定日期與更正關聯。需採交易流水，不應僅以儲存格註記充當帳本。

## GitHub與GAS同步狀態

目前是原始碼備份，GitHub Pages只展示說明，不會執行GAS。尚無這份耗損GAS的Script ID及部署授權，因此沒有建立clasp綁定或GitHub自動推送；試算表ID不能替代Script ID。後續需取得耗損表「擴充功能 → Apps Script → 專案設定」中的指令碼ID，先備份完整線上專案與觸發器，再設定獨立同步。憑證不得提交到公開GitHub。
