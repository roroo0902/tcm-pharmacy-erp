# GitHub Pages 單機試用

網站：https://roroo0902.github.io/tcm-pharmacy-erp/

1. 在「藥品建帳」輸入藥名、廠牌、類別、編號、實際盤點日及期初瓶數。
2. 「進貨登錄」選藥品、發生日、經手人與實際到貨瓶數；確認後入帳。
3. 「每日耗損」與進貨登錄採相同的工作表清單版面：切換科達／天明／富田的單方與複方，搜尋藥名或編號，填固定耗損日期、經手人、原因／備註及各項使用瓶數。數量留白表示本次未耗損；支援編號、原表瓶數、耗損量及更新欄排序、新增品項、重新讀取來源。切換工作表或搜尋不會清掉尚未登錄的數量，摘要含其他廠牌分頁。
   原表瓶數僅供參考，登錄後瓶數以本機帳本計算；首次登錄在確認視窗填入耗損前實際盤點瓶數，不直接沿用 Google 原表。整批確認後一次保存；任一項庫存不足、重複品項、編號／藥名不符、日期早於期初或晚於今天時拒絕整批入帳。既有流水可在交易紀錄沖銷。
   未確認輸入僅保留於本次頁面，重新整理或離開頁面會清除；已確認交易隨完整備份保存。此網站耗損仍只寫入本機帳本，不呼叫耗損 GAS、不扣 Google Sheets 庫存。
4. 「交易紀錄」保留原交易；誤填時以沖銷新增反向交易，再重新登錄正確數量。
5. 定期在「備份與還原」下載完整JSON。還原經確認會取代本機全部資料。

## 儲存範圍

資料只存目前網站來源的localStorage，不傳送至GitHub或Google Sheets。不同瀏覽器、裝置與無痕視窗各自獨立；清除網站資料會遺失紀錄。這是單機試用，沒有登入、多人共用、資料庫備援或正式權限管理，不適用作唯一正式帳本。

使用新版Chrome或Edge。以Web Locks序列化同一瀏覽器多分頁的讀取、驗證、寫入，避免相互覆蓋；瀏覽器無此功能時停止寫入。儲存失敗時顯示錯誤，不顯示成功。備份重載重新驗證帳本。

原Excel的歷史瓶數不預載為目前庫存，也未把650筆資料公開到GitHub。GAS原碼在gas/restock與gas/loss分別保存；本網頁不執行這些GAS、不改原工作表。

## 部署

GitHub Pages使用main分支根目錄。index.html為入口，web/提供樣式與互動，src/inventory.mjs計算瓶數。無外部前端套件與追蹤服務。

執行 `node --test` 驗證核心與備份還原。實際瀏覽器須另外驗證建帳、進貨、耗損、重新載入及響應式版面。

## 藥品名冊
在藥品建帳頁匯入名冊檔，或展開貼上名冊內容。名冊存於本機並隨完整備份匯出；不覆蓋既有庫存與交易。重複匯入相同來源不新增，內容有差異則中止供核對。來源瓶數只作歷史參考，按核對與建帳、確認藥品資訊並輸入實盤日期與瓶數後才啟用。缺編號與重複品項須先核對。
